- **Completed work:**
  - Root cause of the recorded CI failures (3 occurrences on 2026-10-14, runs 38540099697/38641064040/38653793443, job logs inspected; all identical): `focus-persistence/suite` aborted with `InvalidStateError: Storage upgrade is blocked. Close other V2 tabs and reload.` immediately after the "failed additive v1 upgrade" check passed. Category: **test synchronization**, not an application defect and not browser cleanup — the suite closed its v1 probe connection (`unchanged.close()`) while that connection's readonly transaction was still completing, then immediately requested the v1→v2 upgrade through the adapter; the adapter's `onblocked` handler intentionally treats any blocked upgrade as fatal, and under CI load Chromium could still see the closing connection in the database's connection set. Mechanism proven deterministically with a scratch harness (outside the repository): a v1 connection closed with an active transaction followed by an adapter upgrade reproduces the exact error name and message.
  - Fix (`focus-persistence.test.js`, one site): the v1 probe's record read now awaits the transaction's `complete` event (not just the request's `success`) before `close()`, plus one macrotask yield so the closing connection's teardown is ordered before the upgrade request. Every existing assertion is unchanged; the adapter's blocked-is-fatal semantics remain covered by the dedicated deterministic tests (`persistence.test.js` "blocked initialization rejects promptly…" and the focus suite's own blocked cases).
  - Restart-phase profile-lock hardening wired: `run-browser-tests.py` defined `wait_for_profile_release` (commit `124abde`) but never called it — the documented "Restart local identity lost" hardening was dead code. The restart phase now waits (non-fatal, NOTE-only) for the previous phase browser's `Singleton*` locks to release before reusing the profile. The same wait was added to `run-focus-persistence-tests.py`, which reuses one profile across suite→restart→restart-running→restart-paused phases. `run-planner-tests.py` was deliberately left alone: it closes the browser gracefully via CDP `Browser.close` plus `process.wait()` before reusing the profile.
